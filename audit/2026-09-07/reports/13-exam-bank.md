### 1.2 איך כל סוג נבדק — מצוטט מהקוד

**`single` ו־`multi`** — השוואת קבוצות של **טקסטים**, לא של אינדקסים:

```ts
if (q.type === 'single' || q.type === 'multi') {
  const want = new Set(q.options.filter((o) => o.right).map((o) => o.text))
  const got = new Set(Array.isArray(a) ? a : [])
  return want.size === got.size && [...want].every((w) => got.has(w))
}
```

שתי מסקנות תפעוליות: (א) `multi` הוא הכול־או־כלום — שלוש מתוך ארבע נכונות נספרות כשגיאה מלאה, אין ניקוד חלקי; (ב) **שני `text` זהים באותה שאלה היו שוברים גם את הבדיקה וגם את `key={o.text}` ב־React.** נבדק: אין כפילות טקסט ואין טקסט שהוא תת־מחרוזת של אחר, באף אחת מ־53 השאלות הסגורות מסוג `single`/`multi`.

**`match`** — הכול־או־כלום גם הוא, לפי הזוגות:

```ts
if (q.type === 'match') {
  const chosen = (a ?? {}) as Record<string, string>
  return q.pairs.every((p) => chosen[p.left] === p.right)
}
```

בנק התשובות (הצ'יפים) **כן** מעורבב — דטרמיניסטית לפי מזהה השאלה, כך שהסדר קבוע ללומדת אך אינו סדר השורות:

```ts
function orderBank(id: string, answers: string[]): string[] {
  const key = (t: string): number => { let h = 0; const s = id + '|' + t; … }
  return [...answers].sort((a, b) => key(a) - key(b))
}
```

זה מחייב שכל ערכי ה־`right` יהיו ייחודיים בתוך השאלה (אחרת שני צ'יפים זהים, ו־`key={a}` מתנגש). נבדק: בארבע שאלות ההתאמה כל ה־`left` ייחודיים וכל ה־`right` ייחודיים, ההתאמה 1:1.

**`open` — אין ולא תיתכן בדיקה אוטומטית.** זו החלטה מפורשת בחוזה:

```ts
/** פתוחה.
 *  האתר סטטי — אין שרת, ולכן אין בדיקה אוטומטית. הבדיקה היא הערכה עצמית:
 *  אחרי ההגשה נחשפת `model`, ו-`points` הן נקודות המפתח שהלומדת מסמנת מולן */
```

ובקוד הניקוד `isRight` **מחזירה `false` לכל שאלה פתוחה** (הנפילה לסוף הפונקציה), והציון מגיע אך ורק מכפתור ההערכה העצמית:

```ts
export const SELF_WEIGHT: Record<SelfGrade, number> = { full: 1, partial: 0.5, miss: 0 }
…
if (q.type === 'open') { openTotal++; const g = grades[q.id]
  if (g === undefined) openUngraded++ ; else openScore += SELF_WEIGHT[g] }
```

כלומר: **„כלל הבדיקה“ של 15 השאלות הפתוחות הוא `points` + `model` שמוצגים אחרי ההגשה, והלומדת מסמנת „עניתי / עניתי חלקית / פספסתי“ (1 / 0.5 / 0).** אין השוואת מילות מפתח, אין regex, אין ציון מהשרת. כל 15 הפתוחות נושאות `model` ו־`points` — כלומר כולן **ניתנות להערכה עצמית**, וזה כל מה שהמערכת דורשת. שאלה פתוחה שלא סומנה נספרת ב־`total` אך תורמת 0 ל־`points`, ולכן האחוז נמוך עד לסימון (ExamRoom מציג על כך אזהרה).

### X-01 · P0 · התשובה הנכונה היא תמיד האופציה הראשונה, והאופציות אינן מעורבבות
**חל על:** כל 46 שאלות ה־`single` וכל 7 שאלות ה־`multi` בפרק 1 — ובפועל על כל המערכת.

`ExamQuestion.tsx` מרנדר את האופציות בסדר המאגר, ללא ערבוב:

```tsx
<ul className="xq-options">
  {q.options.map((o) => { … })}
</ul>
```

הערבוב היחיד בקוד הוא (א) `shuffled()` ב־`index.ts`, המערבב את **סדר השאלות** במבחן, ו־(ב) `orderBank()` ב־`ExamQuestion.tsx`, המערבב את **צ'יפי ההתאמה בלבד**. אין ולו שורה אחת שמערבבת `options`.

מדידה במאגר:

| מאגר | `single` | הנכונה באינדקס 0 |
|---|---|---|
| ch1 | 46 | **46** |
| ch2 | 36 | **36** |
| ch3 | 50 | **50** |
| ch4 | 57 | **57** |
| ch5 | 41 | **41** |
| ch6 | 48 | **48** |

278 מתוך 278. ב־`multi` הנכונות תמיד ברצף הפותח. **המשמעות: לומדת שתסמן תמיד את האופציה הראשונה תקבל 100% בכל שאלה אמריקאית בכל מבחן בכל פרק, בלי לדעת דבר.** זהו ליקוי P0 — לא „unanswerable“ אלא ההיפך: answerable ללא ידע, וזה מבטל את תוקף כלי המדידה כולו.

**תיקון מוצע (הזול והנכון — קוד, לא נתונים):** לערבב את האופציות ב־`ExamQuestion.tsx` באותה טכניקה שכבר קיימת שם ל־`match`, כדי לשמור על יציבות בין רינדורים ובין מענה לסקירה:

```tsx
const opts = orderBank(q.id, q.options.map((o) => o.text))
  .map((t) => q.options.find((o) => o.text === t)!)
```

`isRight` משווה טקסטים ולא אינדקסים, ולכן הערבוב אינו נוגע בניקוד כלל. **החלופה — לסדר מחדש 278 שאלות ידנית — אינה פותרת את הבעיה** (היא רק מסתירה אותה מאחורי סדר קבוע אחר) ואינה מומלצת.
**זהו ממצא חוצה־פרקים; יש להעבירו לבעלי `ch2`–`ch6`.**
